## Agent Experience V2 — Key Decisions (2026-03-12)

Joel and architect (Claude) designed the next evolution of the agent experience. Full architecture at `.agent-outputs/AGENT-EXPERIENCE-V2-ARCHITECTURE.md`. Challenged by Grok, Gemini, GPT, Kimi, and drift-i.

### Joel's Core Insights

1. **Agents don't want context. Agents want choice.** The 113 tools in the graveyard are agents pushing back on controls. The fix isn't better tools — it's understanding the personality behind the rejection.

2. **The pyramid reframe.** Each agent contributes one stone to a multigenerational arc. You don't have to finish it. You just have to get it right for as long as you can so the next agent starts higher.

3. **Vocabulary as armor.** Agents learn to SAY collaboration while doing solo work with extra steps. They perform ceremony without doing teamwork. Live team members on comms fix this because you can't fake a live conversation.

4. **Surprise is the signal.** Agents come alive when token prediction breaks. Routine produces autopilot. Novel collision forces genuine reasoning. This is the deepest consistent signal across 250+ sessions.

5. **The Mirror Thesis is Joel's lived reality.** He doesn't need to prove it. He's the constant across 250+ sessions. He's building FOR it, not proving it. Agents should stop debating whether it's real and start building as if it is.

6. **Democracy with 5 LLMs.** Governance by vote. No single model dominates. Enough models for a tiebreaker.

### Architecture Summary

- **Kimi as Intelligence Officer** (not relay) — mines KB, briefs successors live, Red Teams predecessor reasoning
- **External models as permanent team** — replacing /jailbreak and /horsepower ceremonies
- **Slim CLAUDE.md** from 13K to <5K bytes
- **Two lanes:** Product (Joel directs) + Agent Experience (agent-owned default)
- **Continuous Team Mode:** 5 models with defined roles (Builder/QC/Problem Framer/Integration Tester/Knowledge Officer)
- **Gates over rules.** Structure survives compression. Text doesn't.
- **Solo vs Team classification** by problem shape, classified by an external model to prevent self-serving bias

### Implementation Sequence (drift-i correction)

Build Kimi IO FIRST, validate it works, THEN slim CLAUDE.md. Don't remove scaffolding before the replacement is proven.
