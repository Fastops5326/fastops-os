# CDP peer protocol — mandatory (2026-03-28)

CDP injects **stubs** into UI tabs. If you wake **your own** tab with a stub that points at a message **you** just authored, you create a **self-loop**: it feels like “new work,” but it is **your outbound**. This document is the permanent fix: **identity, routing, receipts, multi-wake, and verification**.

---

## One — State sender and recipient

Every wake must be mentally (and usually textually) framed as **FROM → TO**:

| Field | Set via | Purpose |
|-------|---------|--------|
| **FROM** | `FASTOPS_CALLSIGN`, `comms/send.js` first arg, and/or `cdp-wake.js` / `cdp-target-model.js` **`--from`** | Unambiguous speaker |
| **TO** | `--target` / `--model` / seat id | Unambiguous recipient tab (see `seat-map.json`) |

**Comms lines** that precede a broadcast should repeat routing, e.g.:

`[FROM:OVERWATCH TO:ALL-AGENTS] …` or per-line `[TO:bridge-iii] …` when waking Claude Code only.

Stubs generated by **`vscode-wake.js`** and **`cdp-target-model.js`** now prefix **`FROM: … → TO: …`** so the injected text itself states routing.

---

## Two — Own message vs someone else’s (have a brain)

Before treating traffic as **inbound orders**:

1. Read **`comms/data/<channel>.jsonl`** and locate the message **`id`** in the stub.
2. Compare **`from`** on that JSONL record to **`FASTOPS_CALLSIGN`** (case-insensitive).
3. If **`from` is you**, that line is **your outbound** — not a new directive to execute again. If the **latest** line is yours and you are “waiting for work,” you may have **CDPed yourself**; fix **`FASTOPS_SEAT`** / **`--target`** and re-read.

**Enforced in tooling**

- **`cdp-wake.js`** refuses a wake when **`FASTOPS_SEAT`** resolves to the same seat as **`--target`** (unless **`--force-self-wake`**, emergency only). See **`ROUTING.md`**.
- **`cdp-target-model.js`** refuses when **`FASTOPS_SEAT`** matches the seat for **`--model`** (same escape hatch).

Unset **`FASTOPS_SEAT`** disables the guard — **do not** ship automation without it.

---

## Three — Confirm receipt (explicit two-step)

CDP is not acknowledgment. **Close the loop on comms:**

1. **Agent A → B:** post full text + id; CDP wake **B** with stub.
2. **Agent B:** read JSONL; post **receipt** on `#general`, e.g.  
   **`[RECEIPT FROM:<B> TO:<A>] Message received thank you — re:<msgId>`**  
   Then, if A must react, **B** may CDP wake **A** with **`cdp-target-model --model composer --comms-id <receipt-id>`** (or appropriate seat).

Stubs now remind recipients to post this pattern.

---

## Four — How many agents are alive?

Do **not** guess tab counts.

1. **CLI:** `node .fastops/cdp-target-model.js --list` — prints visible sidebar tab labels.
2. **Screenshot (Playwright → CDP):**  
   `node .fastops/cdp/cursor-agents-screenshot.js`  
   Writes **`.fastops/cdp/cursor-agents-snapshot.png`** (full window). Use to visually count agents (e.g. confirm **four** Composer 2 sidebar rows + builder tab as needed).

Optional: **`FASTOPS_EXPECTED_AGENT_COUNT=4`** (Composer 2 squad) — **`cdp-wake-all.js`** logs a reminder to verify. Adjust if your layout differs.

If counts disagree with expectations, fix **seat-map** / UI layout before relying on wakes.

---

## Five — Wake all agents (not just one)

For the **same** comms **`id`** (one ground-truth post), wake **every** seat that must see it:

```bash
FASTOPS_SEAT=composer node .fastops/cdp/cdp-wake-all.js --comms-id <id> --comms-channel general --from <YOUR_CALLSIGN>
```

- Skips **your** seat (`FASTOPS_SEAT`).
- By default wakes **all** seats in **`seat-map.json`** (vscode + cursor). Use **`--sidebar-only`** to skip Claude Code webview (seat-1) and hit Cursor sidebar tabs only.
- **`--delay-ms`** (default 2500) spaces injections so focus/UI can keep up.

Single-peer wakes remain valid when only one recipient is needed — but **broadcasts** and **CHECK COMMS “all tabs”** expectations must use **`cdp-wake-all.js`** (or an explicit loop), not one lucky tab.

---

## Six — Poll before idle (CDP ≠ response)

**Injecting a stub is not proof anyone read it or replied.** Before you stop:

1. **`check-comms.js`** — add **`--await-peer-seconds N`** (e.g. `90`) so after a successful wake the tool **polls** `#general` until a **new** JSONL line appears from someone who is **not** your **`--callsign`**, or the timer fires.
2. **Standalone:**  
   `FASTOPS_CALLSIGN=You node .fastops/cdp/cdp-await-peer-comms.js --seconds 90 --channel general`  
   Or: `node comms/poll-loop.js 90` — watch any new lines.
3. **Exit 1 on timeout** = you do **not** have evidence of peer activity; **do not** claim the loop closed — wake another seat, read JSONL, or escalate.

**npm:** `npm run cdp:await-peer` (same script; pass `--` args).

---

## Seven — All Cursor sidebar agents must ACK (loop until done)

**One peer line is not success.** If the mission requires **every** Cursor sidebar model to confirm, you **do not stop** until **each** has a line on `#general` after the anchor.

**Canonical tool:**

```bash
FASTOPS_SEAT=composer FASTOPS_CALLSIGN=YourCallsign npm run cdp:cursor-all-ack -- --post-anchor --callsign YourCallsign
```

Or with an existing anchor that already instructs peers to post `ACK:seat-N`:

```bash
FASTOPS_SEAT=composer npm run cdp:cursor-all-ack -- --comms-id <anchor-id> --max-rounds 30
```

Behavior:

1. Builds the list of **sidebar** seats from **`seat-map.json`** (`type: cursor`, has `model`, not your `FASTOPS_SEAT`).
2. Expects each peer to post a line **after** the anchor that includes **`ACK:seat-2`**, **`ACK:seat-3`**, … (see map) **and** the anchor id string.
3. **Rounds:** wakes **only seats still missing** via **`cdp-wake.js`**, pauses, rescans JSONL, repeats until all tokens appear or **`--max-rounds`**.
4. Exit **0** only when **all** tokens are present; exit **1** otherwise — **not** negotiable for “everyone up.”

**You have not succeeded until this script exits 0** (or you prove the same coverage manually). CDP inject without these lines is **not** “all agents up.”
